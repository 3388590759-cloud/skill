# 文档整理

适用两类目录，共用同一套分类与命名规则：

- **文档/素材型工程**：以方案文档和图片素材为主、没有构建产物的目录（如自媒体、IP 设定、投标资料）。根目录 VERSION 写 `type = docs`。
- **代码工程的 `docs/`**：治理阶段 B 的文档归位按本文 §3 执行。

## 1. 文档型工程与代码工程的差异

| 项 | 代码工程 | 文档型工程 |
|---|---|---|
| 版本管理 | 一个目录 = 一个 git 仓库 | **不用 git**：不 `git init`，不建 `.gitignore` |
| 移出的文件 | 已跟踪 `git rm`，未跟踪进回收站 | **一律进回收站**（[判定规则.md](判定规则.md) §6），包括有唯一内容的旧版 |
| 留底与恢复 | git 历史 | 整理前把清单（路径、大小、SHA-256）写进 scratchpad，失败时按清单搬回 |
| 顶层词表 | `LAYOUT_V1`（[目录布局.md](目录布局.md) §2） | §2，`scan.py` 的 `DOCS_LAYOUT_V1` |
| VERSION | 硬件.协议.固件 | 只声明类型和布局，不填版本三段 |
| 交付物 | `release/` 当前版本，文件名带版本号 | `release/` 只留最近一次对外打包件，文件名带日期 |

VERSION（模板 `templates/VERSION.docs.tmpl`）：

```ini
# one-project 文档型工程声明（不用 git，不填版本三段）
type   = docs
name   = 示例工程
layout = 1
```

- `name`：工程名，用作 `release/` 打包件的文件名前缀，也用来检查文档名有没有带工程名前缀；省略时取目录名。
- 写上 `layout = 1` 表示已整理到本规范：轻检开始拦截回退，体检里的布局项计入待处理。没写 VERSION 的目录用 `scan.py <路径> --docs` 扫，布局项只作建议。

## 2. 顶层词表

单一来源是 `scripts/scan.py` 的 `DOCS_LAYOUT_V1`，本表由 `tests/test_scan.py` 校验两者一致。只建有内容的目录。

| 词 | 含义 | 放什么 | 不放什么 |
|---|---|---|---|
| `docs/` | 文档 | §3 的十类 | 图片素材（→ `assets/`） |
| `assets/` | 素材 | §4 的三个阶段 | 文档、脚本 |
| `tools/` | 生成或处理素材的脚本 | 生成器、回灌、批量裁图等脚本 | 脚本的输出（→ `assets/`） |
| `release/` | 对外发出的打包件 | 最近一次发出的压缩包，`<name>_<内容>_<YYYYMMDD>.zip` | 展开的包目录、更早的包（→ 回收站） |

- 根目录只放 `README.md`、`VERSION`、`CLAUDE.md`（以及 `AGENTS.md`、`LICENSE`）。
- **词表扩展**与代码工程相同：先归入已有词，归不进的用 AskUserQuestion 问用户，写清「含义 / 放什么 / 不放什么」，批准后同时改本表和 `DOCS_LAYOUT_V1`。
- **内容稿件**（视频脚本、公众号文章、封面文案、成片）现在不预留位置，第一次出现时按实际形态走词表扩展。

## 3. docs/ 十类

`scan.py` 的 `DOC_CATEGORIES`，代码工程和文档型工程共用。

| 类 | 放什么 | 版本规则 | 命名 |
|---|---|---|---|
| `协议/` | 通信协议规格书 | 规范本体，多版本并存 | `<协议名>_V<主.次>.<ext>` |
| `接口/` | 纯文字接口说明 | 规范本体，多版本并存 | 可带 `_V<主.次>` |
| `需求/` | 需求规格、交给执行方的需求（如生图需求） | 规范本体，多版本并存；单版本时原地更新 | 可带 `_V<主.次>` |
| `参考资料/` | 外部器件规格书、原理图、厂家资料 | 多版本并存 | 保留原名 |
| `方案/` | 要执行的计划与设计方案 | 同主题只留最终版，原地更新 | 不带日期和版本号 |
| `问题记录/` | 根因与修复 | 同主题只留最终版 | 不带日期和版本号 |
| `记录/` | 过程记录：推进、选型、生图、审查记录，会议纪要 | 同主题原地追加；记的是当时的事实，搬迁时不追改其中路径 | 不带日期和版本号 |
| `手册/` | 使用说明、操作指南、素材使用规范 | 持续更新，只留最新 | 不带日期和版本号 |
| `报告/` | 周报、研究分析、复盘等交付型报告 | 按期多份并存，同一期只留一份 | `报告/<系列>/<期标识>.<ext>`，期标识如 `2026-W44`、`2026-10`、`2026-10-28` |
| `模板/` | 可复用的提示词、文案、封面标题模板 | 只留最新 | 不带日期和版本号 |

区分：**方案**是要执行的计划，**报告**是一次性交付的结论；**问题记录**是根因与修复，**记录**是过程留痕。

命名规则（报告与规范本体之外的六类）：

- 去掉工程名前缀：`示例工程-运营方案.md` → `docs/方案/运营方案.md`，目录已经说明归属。
- 不带日期、不带版本号；版本号和修订历史写在文档头，格式 `> v1.2（2026-10-27）：…`。
- 同主题原地更新，不新建 `-v2`、`-final`、`-续` 副本。

## 4. assets/ 三个阶段

`scan.py` 的 `ASSET_STAGES`。先按阶段分，再按用途分。

| 阶段 | 含义 | 放什么 | 规则 |
|---|---|---|---|
| `参考/` | 给 AI 或外包的输入 | 程序生成的草图、参考图拼版、视觉设定稿 | 能用 `tools/` 脚本重新生成，但被需求文档引用时保留 |
| `原图/` | AI 或外部产出的原件 | 要留存的候选图、未加工的原始文件 | 与 `定稿/` 字节相同的不重复存 |
| `定稿/` | 选定、当前在用的素材 | `定稿/<NN_用途>/…`；根目录只放浏览页 html | 见下 |

`定稿/` 的规则：

- 按用途分子目录，保留序号前缀（`01_角色与基础设定/`、`02_品牌与头像/` …），浏览页放在 `定稿/` 根目录，它的相对链接就不用改。
- **文件名保留原名不改**：任务编号和选型后缀（如 `T2-01R2_角色表情集.png`）能对回需求文档和推进记录。
- 同一素材的多种格式（PNG 和保真 SVG）都是有意交付的，并存；[判定规则.md](判定规则.md) §4「只留源格式」只适用于规范文档。
- **被取代的素材进回收站**，不在 `定稿/` 里设历史归档子目录；取代关系写进 `docs/记录/`。
- 定稿由脚本加工出的正式资产（如像素回灌结果）放进对应用途下的子目录，与 AI 原图并列。

## 5. 拆解素材包

带日期的交付包目录（如 `示例工程_全部定稿素材_20261027/`）拆开归位，包目录本身不保留：

| 包里的东西 | 去向 |
|---|---|
| 按用途分好的图片目录 | `assets/定稿/<原子目录名>/` |
| 浏览页（`00_素材浏览.html` 等） | `assets/定稿/` 根目录，指向已搬走文件的链接按 §7 修 |
| 使用说明 | `docs/手册/`，去掉日期和工程名前缀；内容改成与新布局一致 |
| 推进记录、审查记录 | `docs/记录/`，去掉日期和工程名前缀；正文不改 |
| `SHA256SUMS`、清单 json | 回收站 |
| 历史归档、被取代的素材 | 回收站（§4） |
| 与另一个包逐字节重复的整包 | 回收站 |

以后要再发给别人，从 `assets/定稿/` 现打压缩包放进 `release/`，旧包进回收站。

## 6. 重复文件

- 用 SHA-256 判定（scan 的 `duplicates` 先按大小分组再算哈希）。内容相同的只留规范位置一份：`定稿/` 优先于 `原图/`、`参考/`；`docs/` 优先于包内副本。
- 同名不同内容、看起来相似但哈希不同的，列为争议项问用户。

## 7. 路径与链接修复

| 类别 | 处理 |
|---|---|
| 当前有效的引用：方案、需求、手册的正文，README、CLAUDE.md，浏览页的 `href`/`src` | 改成新路径；指向回收站内容的改为现存对应物（如旧包里的 T4 头像 → `assets/定稿/02_品牌与头像/T4-01R2_账号头像.png`） |
| 文档头的版本历史行（`> vX.Y（日期）：…`） | 保留原文 |
| `docs/记录/`、`docs/报告/` 的正文 | 保留原文 |
| 工程外：Claude memory 里的路径 | 同步改 |
| 工程外：桌面快捷方式、浏览器书签、聊天里发过的路径 | 列给用户，不代改 |

scan 的 `links`：md 链接和 html `href`/`src` 失效计入待处理；md 反引号里的路径失效只列复核，不查版本历史行和 `docs/记录/`、`docs/报告/`。

## 8. README 与 CLAUDE.md

根 README 一份（模板 `templates/README.docs.md.tmpl`），三节：

1. `## 目录结构`：与代码工程同格式的表，第一列用反引号写路径，scan 双向校验
2. `## 权威文档`：哪份是上位方案、各文档的当前版本、改什么去哪份
3. `## 素材取用`：要头像、封面、主页背景、表情包等分别去哪里拿（有 `assets/` 时必需）

子目录不放 README，说明都并入根 README。根目录建 `CLAUDE.md`（模板 `templates/CLAUDE.docs.md.tmpl`），只写本工程特有的规则和权威文档指针。

## 9. 执行流程（文档整理模式）

1. **前置**：确认目标目录；提醒用户关闭占用文件的程序（浏览器里打开的浏览页、图片编辑器）。
2. **扫描**：`scan.py <路径> --json`，未声明 VERSION 时加 `--docs`。
3. **核实**：重复是否逐字节相同（看 `duplicates`）；哪些文件是脚本生成的（看 `tools/` 脚本的输出路径）；文档里哪些地方引用了要搬的路径（`grep -rn`）。
4. **一次确认**（一条消息）：before/after 目录树；搬迁表；回收站清单（条数、体积，单项超过回收站容量要明确写出）；链接改动清单；工程外引用。定不下来的用 AskUserQuestion 逐个问。
5. **留底**：把全部文件的路径、大小、SHA-256 写到 scratchpad（如 `<scratchpad>/manifest_before.tsv`）。
6. **执行**：先建目标父目录，再同盘 `Move-Item -LiteralPath`；按清单进回收站；按 §7 改链接；写 README、VERSION、CLAUDE.md；删除搬空的包目录（空目录直接删）。
7. **验证**：搬迁后的文件 SHA-256 与留底一致；移出项原路径已不存在；条数守恒（保留 + 移出 = 原有）；复扫布局项 0、失效链接 0、规范项 0。
8. **失败恢复**：按清单把文件搬回原路径，回收站里的从回收站还原。
9. **汇报**：按 SKILL.md §8。没有提交哈希，改为写留底清单的路径。

代码工程的 `docs/`：治理阶段 B 按 §3 十类归位（`git mv` + 修链接）。已经按六类整理过的工程不主动重分新四类，scan 对疑似文件只出提示（`reclass_hints`，不计入），下次治理时顺带处理。

## 10. 轻检

声明了 `type = docs` 的工程，在任务收尾跑 `scan.py <路径> --quick`（不限工作区）。它拦这些回退：根目录散放文件、词表外顶层目录、`docs/` 和 `assets/` 第一层的散放文件和词表外子目录、README 目录表漏项、`release/` 里留着旧包。只提示，不删除、不移动。
