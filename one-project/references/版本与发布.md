# 版本与发布

## 1. 版本号：`硬件.协议.固件`

| 段 | 含义 | 规则 |
|---|---|---|
| 硬件 | PCB 版次整数 | 从 1 起，改板 +1；纯软件填 0 |
| 协议 | 对外主协议版本 | 主版本 × 100 + 次版本：V1.4→104，V1.10→110，V2.0→200；不对接设备协议的填 0 |
| 固件 | 本硬件、本协议下的第几版 | 硬件或协议升级时归零 |

- 显示形式：`V2.110.3（协议 V1.10）`。
- 一个工程实现多个协议时，跟**对外主协议**（与上位机或平台对接的那个）走；内部协议（如串口屏）变化只让固件段 +1。
- 上位机/管理软件：硬件段为 0，协议段跟它对接的设备协议走，如 `0.110.3`。
- **冻结规则**：tag 一旦打出，该版本号即冻结；之后任何改动，固件段 +1。测试、联调期间不打 tag，可以复用即将发布的版本号。
- 单片机里协议段用 `uint16` 或字符串存，不要用 `uint8`（V2.56 起会溢出）。

## 2. VERSION 文件

工程根目录，纯文本 `key = value`，`#` 开头为注释：

```ini
# one-project 版本单一来源
product      = ABC-100
version      = 2.110.3
hardware     = 2
protocol     = V1.10
protocol_doc = docs/协议/通信协议规格书_V1.10.md
variant      =
version_files = firmware/ABC-100/User/App/version.h, host/package.json
layout       = 1
```

| 字段 | 必填 | 说明 |
|---|---|---|
| product | 是 | 型号，也是交付物文件名前缀 |
| version | 是 | 三段数字 |
| hardware | 是 | 必须等于版本号第一段 |
| protocol | 是 | `V主.次`；不对接协议填 `无`，此时协议段必须为 0 |
| protocol_doc | 有协议时必填 | 当前采用的协议文档路径（即"注明当前采用版本"） |
| variant | 否 | 变体分支填变体名，必须与分支后缀一致；主线留空 |
| version_files | 否 | 必须包含 version 字面串的文件，逗号分隔，扫描器逐个校验 |
| layout | 否 | 目录布局规范版本，当前为 `1`（[目录布局.md](目录布局.md)）。写上表示已迁到该规范：轻检开始拦截布局回退，体检里布局项计入待处理；不写时布局问题只作建议 |

文档/素材型工程的 VERSION 只写 `type = docs`、`name`、`layout = 1`，不填上表的版本字段，格式见[文档整理.md](文档整理.md) §1。

## 3. 各工具链同步版本号

只做最小修改，让 `version_files` 里能找到 version 字面串：

| 工具链 | 位置 | 写法 |
|---|---|---|
| Keil / CubeMX | 现有版本头文件（没有就在 `User/App/` 下新建 `version.h`） | `#define FW_VERSION "2.110.3"`；需要数值时另加 `FW_VER_HW 2`、`FW_VER_PROTO 110`、`FW_VER_FW 3` |
| Node / Electron | `package.json` | `"version": "2.110.3"` |
| .NET | `.csproj` 或 `Directory.Build.props` | `<Version>2.110.3</Version>` |
| Python | 包的 `__init__.py` 或 `pyproject.toml` | `__version__ = "2.110.3"` |

## 4. 分支与 tag

```
main                        当前最新协议线的开发主线
protocol/v1.4               协议升级时冻结的旧协议线，只修 bug
protocol/v1.10-acme         客户/变体定制，挂在协议线下
tag v2.110.3                正式交付；= 交付物文件名中的版本
tag v2.110.3-acme           变体交付
```

- 允许的分支：`main`、`protocol/v<主>.<次>`、`protocol/v<主>.<次>-<变体>`。变体名只用小写字母和数字。
- 禁止：`codex/*`、`agent/*`、`feat/*`、`fix/*` 等任务分支；中文分支名。AI 直接在当前分支提交。
- tag 用附注 tag，消息与发布提交相同；只在正式交付时打。

**协议升级**（如 V1.10 → V1.11）：

1. 在 `main` 当前提交拉出 `protocol/v1.10` 作为旧线（已存在就跳过）。
2. 在 `main` 上新增 `docs/协议/<协议名>_V1.11.<ext>`，旧版本文档保留。
3. 修改 VERSION：`protocol = V1.11`，协议段改为 111，固件段归零，`protocol_doc` 指向新文档。
4. 提交「构建: 协议升级至 V1.11（V<新版本>）」。

## 5. 提交信息

格式 `类型: 一句话描述`，正文可选（原因 / 影响），全部中文。

| 类型 | 用途 |
|---|---|
| 新增 | 新功能 |
| 修复 | 缺陷修复 |
| 优化 | 性能 / 体验改进，不改功能 |
| 重构 | 结构调整，不改行为 |
| 文档 | 文档增改、docs 整理 |
| 测试 | 测试增改 |
| 构建 | 构建配置、依赖、仓库初始化、规范接入、协议升级 |
| 清理 | 移除过程文件、副本、旧产物 |
| 发布 | `发布: V2.110.3（协议 V1.10）` |

```
修复: 出厂编号断电后丢失

原因：EEPROM 写入未等待完成即复位
影响：参数保存模块
```

## 6. 推送

| 时机 | 行为 |
|---|---|
| 日常提交 | 不推送（用户要求时再推） |
| 打交付 tag | 自动 `git push <远程> <当前分支>`，再 `git push <远程> <tag>` |
| 无远程 | 跳过并说明 |
| 推送失败 | 报告原因，不尝试其他手段 |
| 任何时候 | 禁止 force push；远程分支改名、删除远程分支需单独确认 |

## 7. 发布流程

1. **前置**：`scan.py <工程> --quick` 无问题；工作区干净；当前分支合规；`v<版本>[-<变体>]` 这个 tag 还不存在。
2. **构建**：用当前工程的正式构建方式构建（Keil 批量构建、`npm run build`、`dotnet publish` 等）。不另建验证工程、不复制工程。
3. **命名**：交付物命名为 `<型号>[-<组件>]_V<版本>[_<变体>].<扩展名>`，例如 `ABC-200_V1.104.2.hex`、`ABC-100-Setup_V0.110.3.exe`。写入 `release/`。`release/` 中旧版本文件移出（发布库已有，没有就先补进去）。
4. **发布库**：复制到 `<发布库>\<型号>\`。同名文件已存在：哈希相同跳过，不同就停下问。
5. **提交并打 tag**：
   ```powershell
   git -C <工程> commit --allow-empty -m "发布: V2.110.3（协议 V1.10）"
   git -C <工程> tag -a v2.110.3 -m "发布: V2.110.3（协议 V1.10）"
   ```
   发布前若有版本号同步改动，与发布提交合并为同一个提交（只 add 版本相关文件）。
6. **推送**：按 §6 自动推送分支和 tag。
7. **汇报**：交付物路径、发布库路径、tag、推送结果；提醒"V2.110.3 已冻结，后续改动固件段 +1"。

## 8. 让构建产出带版本号的交付物（接入时一次性设置，需用户确认）

| 工具链 | 最小改动 |
|---|---|
| Keil | 在 `tools/` 下加一个读取 VERSION 的复制脚本，挂到 Options → User → After Build/Rebuild；脚本把 `<OutputDirectory>\<OutputName>.hex` 复制为 `release\<型号>_V<版本>.hex` |
| electron-builder | `"artifactName": "<型号>-Setup_V${version}.${ext}"`，版本取 `package.json`（已与 VERSION 同步） |
| .NET 发布 | 在现有打包脚本的末尾按 VERSION 重命名产物 |
| PyInstaller 上位机 | `host/pack_exe.bat` 输出 `host\dist\<名>.exe`，发布时复制为 `release\<型号>-GUI_V<版本>.exe` |
| 其他 | 在现有打包脚本里改输出名；没有打包脚本的，发布时手动按 §7 命名 |

Keil 复制脚本参考（`tools/release_copy.ps1`；文件保存为 UTF-8 with BOM，否则 PowerShell 5.1 读中文会乱码）：

```powershell
param([string]$HexPath)
$root = Split-Path -Parent $PSScriptRoot
$kv = @{}
Get-Content (Join-Path $root 'VERSION') -Encoding UTF8 | Where-Object { $_ -match '^\s*([^#=]+?)\s*=\s*(.*)$' } |
    ForEach-Object { $kv[$Matches[1].Trim()] = $Matches[2].Trim() }
$name = "$($kv.product)_V$($kv.version)" + ($(if ($kv.variant) { "_$($kv.variant)" } else { '' })) + '.hex'
New-Item -ItemType Directory -Force (Join-Path $root 'release') | Out-Null
Copy-Item -LiteralPath $HexPath -Destination (Join-Path $root "release\$name") -Force
```

Keil After Build 命令示例（layout v1，工程在 `firmware/<板目录>/MDK-ARM/`）：`powershell -NoProfile -ExecutionPolicy Bypass -File ..\..\..\tools\release_copy.ps1 -HexPath .\Objects\proj.hex`。注意 `release/` 里旧版本文件的清理放在发布流程里做，脚本只负责产出当前版本。
