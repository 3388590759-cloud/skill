# 判定规则

扫描器给线索，这里规定怎么核实、怎么处置。核心原则：**依据用途和证据判定，名字只作线索**。

## 1. 保留（白名单）

| 类别 | 内容 |
|---|---|
| 源码与构建 | 源码、构建配置（`.uvprojx`/`.ioc`/`package.json`/`.sln`/`.csproj`…）、依赖锁 |
| 正常编译产物 | 扫描器"保护路径"（由构建配置解析）、`node_modules`、工程级 `.venv`、各类缓存 |
| 正式测试与工具 | `tests/`、长期使用的 `tools/`（开发辅助）；`scripts/` 是正式内容但不在布局词表里，阶段 B 合并进组件或 `tools/`（[目录布局.md](目录布局.md) §9） |
| 根目录 | `README*`、`VERSION`、`CLAUDE.md`/`AGENTS.md`、`.gitignore` 等工具配置 |
| `release/` | 仅当前版本交付物（不入 git） |
| `docs/` 十类 | 协议、接口、需求、参考资料（多版本并存）；方案、问题记录、手册、模板（同主题只留最终版）；记录（同主题原地追加）；报告（按期并存）。见[文档整理.md](文档整理.md) §3 |

活文档也保留：README、当前有效的接口对接文档、使用说明、持续更新的进度文档。

## 2. 移出类别与核实要点

| 类别 | 典型 | 「复核」时必须确认 |
|---|---|---|
| A 验证证据与回执 | `evidence/`、`validation/`、`receipts/`、`attempts/`、截图、测试日志、按日期命名的运行目录 | 打开看：是原始日志/截图/回执就移出；是**结论性**的根因分析，改放 `docs/问题记录/`（同主题合并为最终版） |
| B 任务临时目录 | `.artifacts/`、`.codex-artifacts/`、`.phase*-local/`、`tmp/`、`*-work/`、`.local/`、`spikes/` | `.local/`、`spikes/` 先 `git grep` 目录名，确认没有脚本、配置引用；若存放本地运行所需的配置或密钥，保留并告诉用户 |
| C 历史发布包与构建日志 | `output/`、`publish/`、`installer-stage-*`、带日期的旧固件、`build_*.log`、`*.bak`、`backup/` | 找出**当前版本**的交付物（最新且对应当前代码），它留到阶段 C 移进 `release/`；更早的、真交付过的进发布库（保留原名），未交付的中间包直接删。`backup/` 若是运行中系统的数据库备份，保留并问 |
| D 交接与进度快照 | `handoff/`、交接文档、`DELIVERY-MANIFEST`、`archive/`、`归档*/` | 持续更新的进度文档（如 `00-项目进度与交接.md`）属于活文档，保留；某一天的快照或一次性交接移出。规范目录（`contracts/` 等）下的 `archive/` 是旧版规范，可以保留 |
| E 同主题多轮 | 扫描器 `doc_groups` | 见 §3 |
| F 整工程副本 | 扫描器 `copies`，或候选目录带「⚑内含工程入口」 | 见 §5 |
| G 嵌套仓库 / 参考工程 | `nested_repos`、`reference_projects` | 迁参考库（§8）。先 `git grep` 确认构建没有引用它的源码；有引用就停下问 |

通用核实动作：

- **引用检查**：移出前用 `git grep -n -I -F "<目录或文件名>"` 查看是否被代码、构建脚本、文档引用。被构建或代码引用的一律停下问；被文档引用的，处理后修正链接。
- **运行中检查**：发布目录（`dist`、`publish`）可能正被现场服务或安装程序使用。名字里有 `current`、`live`，或最近 24 小时内有修改的，先问。
- **未提交的唯一内容**：未跟踪的文本类过程文件按"先提交再删"处理，让 git 历史留一份。

## 3. 同主题多轮：选最终版

1. 按文件名里的日期或版本号（V1.0 < 续 V1.1）、修改时间、正文里的"定稿 / 最终 / 实施完成"等字样，判断哪份最新。
2. 看其他文档或 README 引用的是哪一份。
3. 两份**范围不同**的（如"修改方案"和"实施记录"、F4 和 F5），不算同一主题，都留下。
4. 定不下来的列为争议项问用户。其余旧轮次 `git rm`。
5. 留下的那份如果文件名带日期或轮次，在阶段 B 改成不带日期的名字（`git mv`），放进 `docs/方案/` 或 `docs/问题记录/`。

## 4. 规范本体（多版本豁免）

- 包括通信协议规格书、接口契约、产品需求规格书、外部器件规格书（含原理图）。
- **关于**规范的过程文档（符合性核对、新旧对比、接入审查）不享受豁免，按方案类处理。
- 同一版本有多种格式的，只留源格式（客户或设计方发来的原件，如 docx/pdf），派生的 txt/html 转换件删除。
- `(3).docx` 这类暧昧副本：内容和另一份一致就删；不一致的列为争议项。
- 跨工程的同版本协议，每个工程各留一份。扫描器总览中标记"内容不一致"的，要问用户哪份是准的。

## 5. 整工程副本转变体分支

前提：主工程工作区干净，用户已确认副本对应的协议版本和变体名。全程不切换主工作区、不建 worktree。
**顺序**：先完成主工程的阶段 A 清理提交，再转分支，基点用清理后的 HEAD。否则基点里已跟踪的杂物会原样带进变体分支。

**第 1 步：排除副本里的杂物。** 副本自己也带着过程文件、大件和交付物，绝不能带进分支。先扫描副本，生成一份临时排除清单（主工程 `.gitignore` + 副本的杂物路径）：

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8   # 防止 PowerShell 5.1 按 GBK 解码中文路径
$skill  = "<skill>\scripts\scan.py"
$repo   = "<工作区根>\<主工程>"
$copy   = "<工作区根>\<副本目录>"
$sp     = "<会话 scratchpad>"
$ex     = "$sp\variant.exclude"
$j = python -X utf8 $skill $copy --json | ConvertFrom-Json
$junk = @($j.phase_a.candidates.path) + @($j.phase_a.big_untracked.path) + @($j.phase_a.nested_repos.path) +
        @($j.phase_a.reference_projects.path) + @('release/') | Where-Object { $_ } | ForEach-Object { '/' + $_ }
$lines = @()
if (Test-Path "$repo\.gitignore") { $lines += Get-Content "$repo\.gitignore" -Encoding UTF8 }
$lines += $junk
[IO.File]::WriteAllLines($ex, [string[]]$lines, (New-Object Text.UTF8Encoding $false))
```

把 `$junk` 清单给用户过目（这些会随副本目录一起进回收站，不进分支）。

**第 2 步：用临时索引生成变体分支。**

```powershell
$branch = "protocol/v<主.次>-<变体>"            # 变体名只用小写字母和数字
$idx    = "$sp\variant.index"
$gd     = "$repo\.git"
$base   = git -C $repo rev-parse HEAD            # 或选与副本最接近的历史提交
$g      = @("-C", $copy, "--git-dir=$gd", "--work-tree=$copy", "-c", "core.excludesFile=$ex")

$env:GIT_INDEX_FILE = $idx
git --git-dir="$gd" read-tree $base
git @g add --ignore-removal .
$tree   = git --git-dir="$gd" write-tree
$commit = git --git-dir="$gd" commit-tree $tree -p $base -m "新增: 由目录副本 <副本目录名> 转入变体分支 $branch"
git @g diff --name-status $commit                 # 核对 1：只允许出现 D 行
git @g ls-files -o --exclude-standard             # 核对 2：必须为空
Remove-Item Env:GIT_INDEX_FILE
Remove-Item $idx, $ex
git -C $repo branch $branch $commit
git -C $repo -c core.quotepath=false diff --stat $base $branch   # 变体相对基点的改动，给用户看
```

- `D` 行是基点里有、副本里没有的文件，变体分支沿用基点版本。这份列表要告诉用户。
- 两项核对都通过，且用户看过 `diff --stat` 之后，副本目录才按 §6 进回收站。
- `LF will be replaced by CRLF` 警告来自全局 `core.autocrlf=true`，无害。
- 已实测（2026-10-17 沙箱）：主工作区的 HEAD、当前分支、未提交状态全程不变。

## 6. 删除到回收站

```powershell
Add-Type -AssemblyName Microsoft.VisualBasic
$fs = [Microsoft.VisualBasic.FileIO.FileSystem]
$ui = [Microsoft.VisualBasic.FileIO.UIOption]::OnlyErrorDialogs
$rb = [Microsoft.VisualBasic.FileIO.RecycleOption]::SendToRecycleBin
$cx = [Microsoft.VisualBasic.FileIO.UICancelOption]::ThrowException
$fs::DeleteDirectory("<目录绝对路径>", $ui, $rb, $cx)
$fs::DeleteFile("<文件绝对路径>", $ui, $rb, $cx)
```

- 已实测：非交互环境可用，支持中文路径。
- 单项超过所在盘的回收站容量时 Windows 会永久删除，必须在汇总里写明并取得同意。容量每台机器、每个盘都不同，汇总前先查：

  ```powershell
  $drive = (Get-Item -LiteralPath "<要删除的路径>").PSDrive.Name
  $guid  = [regex]::Match((Get-Volume -DriveLetter $drive).UniqueId, '\{[0-9a-fA-F-]+\}').Value
  $bb    = Get-ItemProperty "HKCU:\Software\Microsoft\Windows\CurrentVersion\Explorer\BitBucket\Volume\$guid" -ErrorAction SilentlyContinue
  "{0} 盘回收站上限 {1:N1} GB；不进回收站直接删除 = {2}" -f $drive, ($bb.MaxCapacity / 1024), [bool]$bb.NukeOnDelete
  ```

  读不到注册表项（该盘还没用过回收站）或「直接删除」为真时，按"会永久删除"告诉用户。
- 被占用而删不掉的，报告给用户，不换手段硬删。
- 删除后用 `Test-Path` 逐项确认。

## 7. .gitignore 模板（非 git 工程初始化 / 接入 / 新建时使用）

只忽略**构建产物和依赖**。过程目录**不要**加进去，保持可见，让扫描器发现它们。

模板片段在 `templates/gitignore/`：`common.gitignore`（必选）+ 按工程实际工具链取 `keil`、`iar`、`python`、`node`、`dotnet`，依次拼接；Keil 工程另把扫描报告里的保护路径逐条加入（如 `firmware/<板目录>/MDK-ARM/<Target>/`）。不要把用不到的片段整段照抄。

## 8. 迁往参考库 / 发布库

```powershell
$dst = "<参考库>\<工程名>\<目录名>"      # 发布库：<发布库>\<型号>\<原文件名>
if (Test-Path -LiteralPath $dst) { throw "目标已存在：$dst" }
New-Item -ItemType Directory -Force (Split-Path $dst) | Out-Null
Move-Item -LiteralPath "<工程>\<相对路径>" -Destination $dst    # 同盘移动即重命名，秒级完成；跨盘是先复制后删除，大件先告诉用户
git -C "<工程>" rm -r -q --cached --ignore-unmatch -- "<相对路径>"   # 若曾被跟踪，记录删除
```

- 嵌套仓库连同它的 `.git` 一起迁走，保持独立仓库。
- 发布库里同名文件已存在时：哈希相同就跳过；不同就停下问。
- 两个库都**不放**清单、回执、README 之类的附属文件。来源由目录名（参考库）或文件名（发布库）体现。
